Pipeline

  1. /qa-pilot:generate-tests

    Author the cases

    Reads the tracker task and the code, then writes cases.yaml: at most 25 cases, a required scenario mix, and an assertion in every case.

  2. QA approves the scenario matrix, the write policy and the cases
  3. /qa-pilot:run-tests

    Run against a deployed build

    Turns approved cases into committed Playwright specs and runs them with a trace per case.

Refusals

  1. A verdict without evidence

    Every executed case needs a Playwright trace and a deploy SHA read from the running environment.

    cases[CHECKOUT-ORDER-001].trace: required for a pass verdict. An unevidenced verdict is exactly the unverifiable claim this pipeline exists to prevent.

  2. A run that broke its write policy

    A read-only run that recorded a write, or a run whose guard never reported in, does not publish.

    rule 3: read-only run recorded 2 write(s) in cases[CHECKOUT-ORDER-003]

Split

Evidence stays local

A trace carries the session and every request body it touched, so a production trace is never attached to the tracker, never uploaded by CI, and never committed.

Prose sample

Verdict derivation #

Verdicts are derived from the attempt results, not from Playwright’s own status field, so a config change such as retries cannot turn a flaky case green. Failing in any browser is a failure, never a flake.
